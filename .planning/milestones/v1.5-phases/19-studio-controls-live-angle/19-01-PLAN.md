<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rosbridge/ROS client -> `/opensim/visualizer/open` | Untrusted callers can invoke a native-facing service. |
| opensim_node -> native OpenSim/Simbody adapter | Optional native APIs can throw, block, or be absent. |
| opensim_node -> status/IK publishers | Visualizer state must not corrupt the trusted product IK path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Elevation of privilege | visualizer Trigger | high | mitigate | Fixed argument-free service delegates only to the pre-owned adapter; no command, path, shell, WSL, process, or user-supplied executable input is accepted. |
| T-19-02 | Denial of service | repeated service calls | medium | mitigate | One bounded callback and idempotent adapter operation; no resource creation per retry and no duplicate service registration. |
| T-19-03 | Tampering | adapter status/result | medium | mitigate | Convert outputs to bool + normalized string and keep the JSON-safe status schema; tests cover exceptions and repeated calls. |
| T-19-04 | Denial of service | native adapter failure | high | mitigate | Catch native exceptions at the adapter and node callback boundaries; tests assert calibration, IK status, and JointState publishers remain operational. |
| T-19-SC | Tampering | package supply chain | low | accept | No npm/pip/cargo package installation is permitted or required by this plan. |

No high-severity threat may remain unmitigated; Task 2 verification is blocking for T-19-01 and T-19-04.
</threat_model>
