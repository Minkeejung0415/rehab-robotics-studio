<interfaces>
`RosbridgeDataSource.callService(service, args, type?, toResult?)`:
- Recording uses `std_srvs/srv/SetBool` with `{ data: on }`.
- Calibration must use type `std_srvs/srv/Trigger` and args `{}`.
- Trigger response maps `values.success` / `values.message` (same shape as SetBool result fields).

`appDataSource.ts` already exports `setHardwareRecording` pattern — mirror with:
- `captureOpenSimCalibration(): Promise<{ success: boolean; message: string }>`
- `clearOpenSimCalibration(): Promise<{ success: boolean; message: string }>`
returning failure when rosbridge inactive (same message style as recording).

`OpenSimStatusSnapshot` (health.ts) today has sensors/visualization/joint_angle_deg — extend with optional:
```typescript
calibration?: {
  state?: string;
  reason?: string;
  known_pose?: string;
  sample_count?: number;
  calibration_id?: string | null;
  has_offsets?: boolean;
};
```

HealthPanel currently hardcodes `OpenSim IK angles` → `Waiting (requires calibration)` — keep that product-angle waiting text; ADD separate Calibration status rows from `openSim.calibration`.
</interfaces>
