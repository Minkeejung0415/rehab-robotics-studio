## State Badge Rules

### Panel-Level State Badge (Header)

Displayed as `.motor-pill` or `.status-badge` in the `.dash-head` right slot.

| State | Label | CSS Class Modifier | Trigger Condition (from D-19) |
|-------|----|---------------------|-------------------------------|
| No model | NO MODEL | `motor-pill fault` | `catalogModelHash === null` |
| Draft | DRAFT | custom: `border-color: #e0a64a55; color: #e0a64a` | any row has `mappingStatus === 'draft'` |
| Saved | SAVED | custom: `border-color: #4a90d655; color: #4a90d6` | no drafts, `mappingRevision > appliedRevision` |
| Applied | APPLIED | `motor-pill enabled` (green) | `appliedRevision === mappingRevision`, all assigned rows applied |
| Runtime Ready | RUNTIME READY | custom: `border-color: #46c47a; color: #46c47a; font-weight: 600` | Applied + all assigned devices have `ikValid === true` |

Evaluation priority (highest wins): No model > Draft > Saved > Applied > Runtime Ready.

These badges use `role="status"` and `aria-live="polite"` to announce state changes to screen readers.

### Per-Row Status Badge (Column 7)

Displayed as `.status-badge` with an inline style override for color (no new CSS classes needed — use inline style on the badge's border and color properties).

| `mappingStatus` | Label | Color | Border color |
|----------------|-------|-------|--------------|
| `unassigned` | UNASSIGNED | `#5e686d` | `#5e686d55` |
| `draft` | DRAFT | `#e0a64a` | `#e0a64a55` |
| `saved` | SAVED | `#4a90d6` | `#4a90d655` |
| `applied` | APPLIED | `#46c47a` | `#46c47a55` |
| `runtime_ready` | READY | `#46c47a` + `font-weight: 600` + `letter-spacing: 0.02em` | `#46c47a` (solid) |

When `connectionState` is `'disconnected'` and the row came from the offline mapping (not the live fleet registry), overlay the status badge with an additional "Offline" label: render two stacked badges or append "/ Offline" to the status text in muted color (`#5e686d`). The primary status badge color is unchanged.

Per-row badges use `role="status"` and `aria-label="{deviceId} mapping status: {label}"`.

## Interaction Contracts

### Tab Addition (D-01)

In `App.tsx`:
- Extend `WorkspaceTab` type to `'diagram' | 'panel' | 'mapping'`.
- Add a third `<button className={`tab${activeTab === 'mapping' ? ' is-active' : ''}`}` with label "Sensor Mapping".
- Add a third branch: when `activeTab === 'mapping'`, render `<main className="workspace workspace--mapping"><MappingWorkspace /></main>`.
- Default `activeTab` remains `'diagram'` — no change to existing default.

### Segment Selector (D-16)

```tsx
<select
  value={draftSegment ?? backendSegment ?? ''}
  disabled={notUsedEffective || catalogFrameList.length === 0}
  aria-label={`Segment for device ${deviceId}`}
  onChange={(e) => {
    setDraftSegment(deviceId, e.target.value, frameForSegment(e.target.value));
    // also uncheck Not Used if a real segment is selected
  }}
>
  <option value="">— Select segment —</option>
  {catalogFrameList.map(f => (
    <option key={f.path} value={f.path}>{f.name}</option>
  ))}
</select>
```

When `catalogFrameList.length === 0`:
- Show a single disabled `<option>`: "Model not loaded"
- `<select>` is disabled with `opacity: 0.45` (matches `.btn:disabled`)

When "Not used" checkbox is checked, the `<select>` is visually disabled but retains its last value in the DOM (so the Save button can still send the correct payload). `draftNotUsed = true` and `draftSegment = null` in the store.

`<select>` CSS: same as `.node-imu-controls select` — `border: 1px solid #3b484e; background: #111416; color: #dfe6ea; padding: 3px 4px; width: 100%; font: inherit`.

Focus-visible: `outline: 2px solid #4a90d6; outline-offset: -2px` (no border-radius per project style).

### Not Used Checkbox (D-16)

```tsx
<input
  type="checkbox"
  checked={notUsedEffective}
  aria-label={`Mark ${deviceId} as not used`}
  onChange={(e) => {
    setDraftNotUsed(deviceId, e.target.checked);
    // if checking, draftSegment is cleared in store action
    // if unchecking, draftSegment remains null (operator re-selects)
  }}
/>
```

`notUsedEffective` = `draftNotUsed ?? (backendState === 'not_used')`.

When checked:
- The row's `<select>` becomes `disabled`.
- The "Save" button becomes enabled (draft is present: `draftNotUsed !== null`).

### Per-Row "Save" Button (D-13, D-14)

Button is enabled only when: `draftSegment !== null || draftNotUsed !== null`.

```tsx
<button
  className="mini-btn"
  style={hasDraft ? { borderColor: '#4a90d655' } : undefined}
  disabled={!hasDraft || isSaving}
  aria-label={`Save assignment for device ${deviceId}`}
  onClick={() => handleSave(deviceId)}
>
  {isSaving ? 'Saving…' : 'Save'}
</button>
```

On click flow (D-14):
1. Set `isSaving = true` on the row (local UI state, not store).
2. Call `callMappingSetAssignment(deviceId, segment, frame, state)`.
3. On `outcome === 'ok'`: call `clearDraft(deviceId)`. The row transitions from `draft` to `saved` automatically on the next `/rehab/mapping/current` subscription update.
4. On `outcome !== 'ok'`: display the `detail` field as an inline error below the segment cell. Draft is not cleared.

Per-row inline error: `<span className="health-error" role="alert" style="font-size: 10px; display: block; margin-top: 2px">{errorText}</span>` placed beneath the `<select>` in column 5.

While saving, the "Save" button shows "Saving…" and is disabled. The `<select>` remains interactive (operator can adjust draft while save is in flight — the new value will require another Save click).

### Per-Row "Identify" Button (D-17, D-18)

```tsx
<button
  className="mini-btn"
  disabled={identifyBusy}
  aria-label={`Identify device ${deviceId}`}
  onClick={() => handleIdentify(deviceId)}
>
  {identifyBusy ? '…' : 'Identify'}
</button>
```

On click:
1. `setIdentifyBusy(deviceId, true)`.
2. Call `rosbridgeDataSource.callIdentifyDevice(deviceId)`.
3. On completion: `setIdentifyResult(deviceId, outcome)` and `setIdentifyBusy(deviceId, false)`.
4. After 5 000 ms: `setIdentifyResult(deviceId, null)` (auto-clear via `setTimeout`).

Identify result display: a `<span>` in the Identify column below the button, rendered with `font-size: 10px; color: #8b969c; display: block; margin-top: 2px`. When `identifyResult` is null, this span is absent.

Outcome text mapping (display label from raw outcome string):
- `"confirmed"` → "Confirmed" (`color: #46c47a`)
- `"timeout"` → "Timeout" (`color: #e0a64a`)
- `"offline"` → "Offline" (`color: #5e686d`)
- `"unsupported"` → "Unsupported" (`color: #8b969c`)
- `"rejected"` → "Rejected" (`color: #ec5a5a`)
- Any other → the raw outcome string in muted color

### "Apply Mapping" Button (D-15)

```tsx
<button
  className="btn"
  style={{ borderColor: applyEnabled ? '#4a90d6' : undefined }}
  disabled={!applyEnabled || applyStatus === 'applying'}
  aria-label="Apply mapping to runtime"
  onClick={() => handleApply()}
>
  {applyStatus === 'applying' ? 'Applying…' : 'Apply Mapping'}
</button>
```

`applyEnabled` = `applyStatus !== 'applying' && !calibrationInterlocked && mappingRevision > 0`.

On click (D-15):
1. `setApplyStatus('applying')`.
2. Call `callMappingApply(mappingRevision)`.
3. `outcome === 'applied'` → `setApplyStatus('idle')` + `clearAllDrafts()`.
4. `outcome === 'stale_revision'` → `setApplyStatus('error', 'Mapping changed since last refresh. Reload and retry.')`.
5. `outcome === 'recording_active'` → `setApplyStatus('error', 'Cannot apply while recording is active. Stop recording first.')`.
6. `outcome === 'calibration_active'` → `setApplyStatus('error', 'Cannot apply during calibration capture. Wait for calibration to complete.')`.
7. Any other outcome or timeout → `setApplyStatus('error', detail ?? 'Apply failed — check ROS connection.')`.

Apply error display (footer): `<span className="health-error" role="alert" aria-live="assertive" style="font-size: 12px; align-self: center">{applyError}</span>`. Present only when `applyStatus === 'error'`. Clears on next successful apply or when operator retries.

### "Reset" Button (Destructive, D-15)

Two-click confirmation pattern (inline, no modal):

State 1 (idle): `<button className="btn" aria-label="Reset all assignments">Reset</button>`

On first click: button transitions to confirm state for 5 s.

State 2 (confirm): `<button className="btn" style={{ borderColor: '#ec5a5a55', color: '#ffd9d9' }} aria-label="Confirm reset all assignments">Confirm Reset</button>`

On second click in confirm state: call `callMappingReset(catalogModelHash)`. On `outcome === 'ok'`, the backend re-publishes `/rehab/mapping/current` with all assignments cleared; the store updates automatically. On error, show inline error in footer alongside Apply error.

After 5 s without a second click, revert to State 1 automatically.

### Interlock Warning Banner (D-15, MAP-06)

When `calibrationInterlocked === true` (sourced from `calibrationStatus.state === 'capturing'`), render a banner directly above the footer buttons:

```tsx
<div
  className="node-imu-pending"
  role="status"
  aria-live="polite"
  style={{ fontSize: '12px', padding: '6px 10px', borderTop: '1px solid #23292d' }}
>
  Apply blocked — calibration capture is active.
</div>
```

`node-imu-pending` from `app.css` provides `color: #e0a64a`. The banner is absent when `calibrationInterlocked === false`.

## Duplicate Segment Detection (D-21)

Duplicate detection is client-side and immediate — no backend round-trip.

Condition: two or more rows share the same effective segment value. Effective segment = `draftSegment ?? backendSegment` when `draftNotUsed` is not true and `backendState !== 'not_used'`.

Display: inline below the `<select>` in column 5 for each row that has a duplicate:
```tsx
<span
  className="node-imu-pending"
  role="alert"
  style={{ fontSize: '10px', display: 'block', marginTop: '2px' }}
>
  Segment already assigned to another device.
</span>
```

`node-imu-pending` provides `color: #e0a64a`. This warning appears immediately on selector change and disappears when the duplication is resolved. It does not block Save — that is the backend's authoritative rejection role.

## Reconnect and Offline Behavior (D-23, D-24)

### On Disconnect (D-24)

When rosbridge disconnects (`onConnectionChange(false)`):
- All rows get `connectionState: 'disconnected'` via `updateFromFleetRegistry` with an empty devices array, or via an explicit action.
- Rows remain fully visible in the table.
- Column 3 shows "disconnected" in `#ec5a5a`.
- Status badge is unchanged (mappingStatus is preserved).
- An additional "Offline" suffix or badge is appended in column 7 per the badge spec above.
- The "Apply Mapping" button remains in its current state. If the rosbridge is disconnected, `callMappingApply` will fail; the error is shown in the footer.
- Draft changes are preserved — do not clear `draftSegment`, `draftNotUsed`, or any other draft state.

### On Reconnect (D-23)

When rosbridge reconnects:
- Do not clear `mappingStore.rows`.
- The latched `/rehab/mapping/current` topic replays and `updateFromMappingCurrent` overwrites `backendSegment`, `backendFrame`, `backendState`, `mappingRevision`, `appliedRevision`.
- `draftSegment` and `draftNotUsed` remain intact; the store recomputes `mappingStatus` per the D-07 rules.
- No special UI message is required — the badge transitions are the feedback.

## Responsive and Overflow Behavior

The device table has a fixed `min-width: 860px` (9 columns at declared widths). At viewport widths below 860px the outer `.mapping-table-wrap` scrolls horizontally. The header and footer do not scroll — they are sticky at the top and bottom of the workspace column.

Table header stickiness:
```css
.mapping-table thead th {
  position: sticky;
  top: 0;
  z-index: 2;
  background: #1a1f23;
}
```

MappingWorkspace header stickiness: not sticky — it scrolls with the workspace. The workspace is a flex column; only the table wrap scrolls.

At viewport width below 768px, per-row button minimum tap target height is 44px:
```css
@media (max-width: 768px) {
  .mapping-table .mini-btn { height: 44px; padding: 0 8px; }
}
```
