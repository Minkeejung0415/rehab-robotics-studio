- D-20-01: eFuse/base MAC is the stable identity; internal form is `esp32:aabbccddeeff`, display form is `AA:BB:CC:DD:EE:FF`.
- D-20-02: base, STA, AP, ESP-NOW transport MAC, role, IP/route, slot, and deprecated low-32-bit `slave_id` remain separate metadata.
- D-20-03: Identify carries a bounded command ID, exact full-MAC target, and duration; only target application ACK can produce `confirmed`.
- D-20-04: Outcomes are `confirmed`, `sent_unconfirmed`, `timeout`, `offline`, `unsupported`, `rejected`, and `invalid_target`.
- D-20-05: Duplicate command IDs are idempotent; a different accepted command may replace the deadline, but a replay cannot extend it.
- D-20-06: Identify is loop-owned and non-blocking, clamps to 1000-5000 ms with 3000 ms default, restores prior LED state, and never changes acquisition/recording.
- D-20-07: The official Seeed Studio XIAO ESP32S3 board target uses onboard user LED GPIO 21 active-low behind an exact board-target guard; every other board target remains unsupported.
- D-20-08: New packets require exact length, explicit version, and packet_size; mixed firmware preserves existing acquisition and recording.
</locked_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host text command -> Master firmware | Untrusted target, command ID, and duration cross into device control. |
| Master ESP-NOW -> target firmware | Radio packets can be malformed, replayed, duplicated, lost, or addressed to the wrong peer. |
| Identify state -> acquisition/recording loop | Diagnostic LED work shares a timing-sensitive firmware loop. |
