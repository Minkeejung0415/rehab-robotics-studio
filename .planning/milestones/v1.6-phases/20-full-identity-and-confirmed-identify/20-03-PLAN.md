<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Relay text/binary stream -> ROS bridge | Untrusted mixed data can attempt to forge identity or terminal replies. |
| ROS client -> Identify service | Client controls command ID, target, and duration. |
| Verified identity -> ROS topic namespace | A malformed/colliding identity could misroute sensor data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-11 | Spoofing | identity handshake/session binding | high | mitigate | Strict counted self/peer/end parser plus optional expected-self-ID match before accepting the stream; peers cannot bind sessions. |
| T-20-12 | Tampering | Identify service input | high | mitigate | Bound and validate command ID, exact target, duration, protocol, outcome, and detail before I/O/state changes. |
| T-20-13 | Repudiation | asynchronous replies | high | mitigate | Match both command ID and target; unmatched/late replies cannot settle a request. |
| T-20-14 | Denial of service | control queue/parser | high | mitigate | Bounded line/token lengths, serialized command lock, bounded timeout, and preserved binary resync. |
| T-20-15 | Elevation of privilege | publisher ownership boundary | high | mitigate | Preserve existing role publishers and test that Phase 20 creates no canonical per-MAC publisher lifecycle; Phase 21 owns instantiation. |
| T-20-SC | Tampering | package/tool installs | low | accept | Primitive ROS fields use existing dependencies; no install is authorized. |
</threat_model>
