# Phase 26 — UI Design Contract

> Visual and interaction contract for trustworthy signal identity, unit availability, channel validity, and applied-mapping provenance. Generated by gsd-ui-researcher for SIG-01 through SIG-05.

---

## Scope and Non-Goals

Phase 26 adds a compact **Signal Contract** inspector to the existing Front Panel and defines reusable identity, provenance, unit, and availability primitives for later viewer/export surfaces. The inspector shows the latest accepted canonical sample for sources observed in the current browser session; it is a contract-proof and diagnostics surface, not a fleet browser.

This phase does **not** add waveform traces, multi-source comparison, scrolling history, time-window controls, pause, zoom, autoscale, display-rate diagnostics, saved/offline source discovery, export controls, or a new top-level navigation tab. Those belong to Phases 28–30. It also does not relabel the existing Mapping Workspace or expose draft assignments as signal identity.

The non-negotiable visual rule is: a value that is absent, invalid, uncalibrated, or unsupported must look unavailable. It must never be rendered as zero, an identity quaternion, or a valid SI measurement.

## Typography

Phase 26 uses exactly four existing sizes and two weights: regular `400` and semibold `600`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Metadata | 10px | 400 | 1.4 | Units, epochs, revisions, time origin, availability reason |
| Compact label | 11px | 600 | 1.2 | Group labels, status badges, segmented controls |
| Body / value | 12px | 400 | 1.5 | Full MAC, exact segment/frame, numeric values, state copy |
| Section heading | 13px | 600 | 1.2 | `Signal Contract` and source-card headings |

Full MACs, exact segment/frame identifiers, sequence/timing values, epochs, and numeric channel values always use the monospace stack. Do not abbreviate the MAC or reduce it below 12px. Uppercase is limited to compact state badges (`AVAILABLE`, `RAW ONLY`, `UNAVAILABLE`, `INVALID`); explanatory copy remains sentence case.

## Copywriting Contract

| Element | Exact copy |
|---------|------------|
| Panel heading | `Signal Contract` |
| Primary mode action | `Show SI Values` |
| Alternate mode action | `Show Raw Counts` |
| Provenance disclosure, collapsed | `Show Provenance` |
| Provenance disclosure, expanded | `Hide Provenance` |
| Empty state heading | `No canonical samples` |
| Empty state body | `Start acquisition or check the ROS bridge connection.` |
| Rejected-sample heading | `Sample rejected` |
| Rejected-sample body | `{reason}. Values were not displayed. Check the source contract and ROS connection.` |
| Applied label, assigned | `Applied r{revision} · {segment} / {frame}` |
| Applied label, unassigned | `Applied r{revision} · Unassigned` |
| Magnetometer SI unavailable | `SI unavailable — {calibration or sensitivity reason}. Raw counts remain available.` |
| Quaternion capability absent | `Quaternion unavailable — source capability not declared.` |
| Quaternion transiently invalid | `Quaternion invalid — {validity reason}. No orientation value is displayed.` |
| Destructive confirmation | None — Phase 26 introduces no destructive action |

Reason text is mapped from allowlisted machine codes; never render raw JSON, `undefined`, an exception stack, or an unbounded backend detail. Human mappings must include at least: `capability_absent` → `source capability not declared`; `stale` → `sample is stale`; `missing` → `value is missing`; `malformed` → `value is malformed`; `non_finite` → `value is not finite`; `zero_norm` → `quaternion norm is zero`; `norm_out_of_range` → `quaternion norm is outside the valid range`; `config_invalid` → `sensor sensitivity is invalid`; `calibration_missing` → `calibration provenance is missing`; `calibration_invalid` → `calibration provenance is invalid`.

Use `counts`, `m/s²`, `rad/s`, and `µT` exactly. Never show `µT` next to a value unless both sensitivity and calibration provenance validate.

## Layout Contract

### Panel

- Reuse `.dash-panel`, `.dash-head`, `.status-badge`, `.kv-grid`, `.btn`/`.mini-btn`, `.validation-msg`, and existing status colors where semantically correct.
- Apply the Phase 26-specific override `.dash-panel.signal-contract-panel { padding: 8px; }` so this surface does not inherit the existing 10px `.dash-panel` inset.
- Place `SignalContractPanel` first in `Dashboard`, before Acquisition Health, so trust/availability is read before derived readouts.
- Maximum width remains the existing Front Panel width of 960px. No new tab, sidebar, modal, toast, or floating overlay.
- Panel heading row contains `Signal Contract` left and a compact summary right: `{n} accepted` or `{n} accepted · {n} rejected`. Rejection count uses fault color and text.
- Empty state uses 16px padding and muted body text; it does not synthesize a placeholder device.

### Source card

- One card per full MAC observed through accepted canonical samples during the current browser session. This is not a saved/offline fleet list.
- Card surface is `#16191b`, border `1px solid #23292d`, square corners, 16px internal padding, and 24px between cards.
- Header first line: canonical full MAC in 12px monospace, never truncated, shortened, role-based, or replaced by IP/connection order.
- Header second line: exact applied mapping label. Use the per-sample `appliedMapping` snapshot only. Segment and frame are both visible; if unassigned, show `Unassigned` rather than a role-derived body part.
- Mapping epoch is always visible in the compact header as `Mapping epoch {n}`. Reconnect epoch is always visible as `Reconnect epoch {n}`. Revision/epoch labels remain visible even if their value is zero.
- At widths below 620px, the header wraps into stacked rows. Full MAC remains fully visible using `overflow-wrap: anywhere`; it never ellipsizes.

### Latest-channel table

- This is a latest-sample value table, not a chart. It has four group rows: Acceleration, Angular rate, Magnetic field, Quaternion.
- Each group row has: 112px group/status column, fluid component-value columns, and a 168px unit/availability column at desktop widths.
- Component labels and values are inseparable pairs (`ax 1234`, `gx 0.24`). Values use monospace and tabular numerals.
- Unavailable components render an em dash `—`; never `0`, `0.0`, `NaN`, or blank.
- At widths below 768px, each group becomes a stacked block with label/status first and values second. Horizontal scrolling is not required for this Phase 26 table.

### Provenance details

- `Show Provenance` expands an inline bordered value well directly below the current source card; no modal or tooltip.
- Always list: schema version, full MAC, sequence and sequence origin, acquisition time and acquisition clock (or explicit `Unavailable`), bridge monotonic time, reconnect epoch, mapping provenance epoch, applied revision, exact segment, exact frame, model hash, channel capabilities, and validity reason codes.
- This disclosure exists for verification and debugging. It is collapsed by default and does not change acquisition, buffering, recording, mapping, or OpenSim input.

## Visual Identity and Provenance Rules

1. The canonical `esp32:<12 lowercase hex>` identity is the primary source label everywhere. A human-friendly role may appear only as tertiary metadata and never replaces the full MAC.
2. The body-part label is exactly `segment / frame` from the sample's authoritative applied snapshot. Never read `draftSegment`, draft `assignments`, role aliases, or the mapping editor's current selection.
3. The source card must visually bind MAC, applied label, applied revision, mapping epoch, and reconnect epoch in the same header region. A value row without this header is non-compliant.
4. Historical/future consumers reuse the label carried by each sample. Applying a mapping may change subsequent card headers, but must not mutate labels already owned by buffered samples.
5. Unassigned is a real state: `Applied r{revision} · Unassigned`. Do not display `Unknown body part`, infer from master/slave, or omit the line.
6. Reconnect and mapping provenance are independent. Render both even when they increment at the same time.

## Unit Interaction Contract

- Default every newly observed source card to `Show Raw Counts`; raw signed counts are authoritative.
- The unit control is a two-button segmented control with visible labels `Show Raw Counts` and `Show SI Values`, `aria-pressed`, and one selected state. It affects only the inspector presentation.
- Changing unit mode must not change acquisition, canonical samples, recording, OpenSim input, conversion configuration, or mapping state.
- Acceleration SI is `m/s²` and angular-rate SI is `rad/s`; enable SI display only when the validated range/sensitivity contract is available for that sample.
- Magnetometer raw counts remain visible when magnetometer capability is present even if SI is unavailable. Show `RAW ONLY` and the exact unavailable sentence; do not append `µT` to an em dash.
- Magnetometer SI becomes selectable/renderable only when both sensitivity and calibration provenance validate. `magnetometer capability present` alone is insufficient.
- If SI is selected and a later sample loses SI validity, retain the operator's selected mode but replace affected values with em dashes and the explicit unavailable reason. Do not silently fall back to raw while leaving the control on SI.
- If no group in the current source has validated SI, disable `Show SI Values`, keep raw selected, and expose the reason in the control's accessible description.
- Unit preference may be local to the source card for Phase 26. Cross-device synchronized unit state is deferred to Phase 29.

## Availability and Invalid-State Matrix

| Group/state | Badge | Values | Required explanation |
|-------------|-------|--------|----------------------|
| Accel/gyro raw accepted | `AVAILABLE` | Exact signed counts | Unit `counts` |
| Accel/gyro SI validated | `AVAILABLE` | Deterministic converted values | Unit `m/s²` or `rad/s` |
| Accel/gyro SI config invalid | `RAW ONLY` | Raw view remains; SI view shows `—` | `SI unavailable — sensor sensitivity is invalid. Raw counts remain available.` |
| Magnetometer capability absent | `UNAVAILABLE` | `—` for mx/my/mz | `Magnetometer unavailable — source capability not declared.` |
| Magnetometer capable, raw valid, calibration absent/invalid | `RAW ONLY` | Raw counts in raw mode; `—` in SI mode | Exact magnetometer SI-unavailable copy |
| Magnetometer SI fully validated | `AVAILABLE` | Converted mx/my/mz | Unit `µT` |
| Quaternion capability absent | `UNAVAILABLE` | `—` for qw/qx/qy/qz | Capability-absent copy |
| Quaternion capable but stale/missing/malformed/non-finite/zero-norm/bad norm | `INVALID` | `—` for all quaternion components | Exact validity reason; no orientation displayed |
| Quaternion capable and current value valid | `AVAILABLE` | Received component order qw/qx/qy/qz | Unit `unitless` |
| Required canonical identity/timing invalid | `REJECTED` notice, no source-card update | No values | Rejected-sample copy with allowlisted reason |

Capability absence uses muted text and `UNAVAILABLE`; transient data invalidity uses fault text and `INVALID`. These states must remain machine-readable and visually distinct. Do not hide the difference behind one generic `No data` label.

Quaternion rules are fail-closed: never normalize or fabricate an identity quaternion for display; never render `[1, 0, 0, 0]` unless those are received values and the declared capability plus finite/norm policy validates them.

## Feedback and Error Behavior

- Accepted samples update the latest-value table in place without animation and without moving focus.
- A rejected sample does not replace the last accepted sample. Keep the last accepted values visually present but add `Last update rejected` with the bounded reason and timestamp in the source card. If no accepted sample exists for that MAC, show only the rejection notice, not a value card.
- Rejection feedback belongs in the persistent panel and existing System Log; do not use the transient toast as the sole report.
- When acquisition time is not genuinely supplied, show `Acquisition time: Unavailable` and separately show the labelled bridge monotonic time. Never relabel browser or bridge receipt time as acquisition time.
- A source's sequence/time reset with a higher reconnect epoch is valid provenance, not a validation error. The header must update the reconnect epoch; waveform gaps are deferred to Phases 28–29.
- Applying a new mapping updates only samples accepted after the new applied snapshot. Do not animate or announce draft/save edits as label changes.

## Accessibility

| Element | Contract |
|---------|----------|
| Panel summary | `role="status"`, `aria-live="polite"`; announce count changes, not every sample |
| Source card | `<section aria-labelledby="signal-source-{safeMac}">`; heading contains full MAC |
| Applied mapping line | Accessible text includes `Authoritative applied mapping revision {revision}, segment {segment}, frame {frame}` or `unassigned` |
| Unit segmented control | Group label `Display units for {fullMac}`; each button uses `aria-pressed`; disabled SI button has an `aria-describedby` reason |
| Availability badge | Badge text remains in the accessible name; color is supplementary |
| Invalid/unavailable reason | Persistent inline text connected to the affected group using `aria-describedby` |
| Rejected sample | `role="alert"` for a newly changed reason; do not repeatedly announce identical rejection codes per sample |
| Provenance disclosure | Native `<button aria-expanded>` and an identified details region |

Keyboard order within a card is unit control, provenance disclosure, then the next card. Latest numeric values are read-only and do not enter the tab order. Focus-visible uses a 2px `#4a90d6` inset outline. Respect reduced-motion preferences; Phase 26 requires no motion.

## Responsive and Overflow Contract

- Desktop/tablet: source cards use the full existing 960px Front Panel content width.
- Below 768px: controls become 44px high, channel groups stack, and provenance key/value rows become one column.
- Below 620px: full MAC, exact segment/frame, and epoch metadata wrap; they never ellipsize or collapse to a shortened identifier.
- Long model hashes may wrap anywhere. Exact segment/frame strings wrap and remain fully inspectable; a title-only tooltip is insufficient.
- No viewport size may hide the unavailable/invalid reason while leaving only an em dash or status color.

---

## Implementation Boundaries

- Render only from a strictly validated canonical sample result. Legacy `Frame.imu`, `numeric(...)` zero-defaults, browser receipt time fallbacks, and role aliases are forbidden inputs to these Phase 26 components.
- Store or pass the applied mapping snapshot on each canonical sample. `MappingWorkspace` may continue to edit drafts independently, but the signal inspector must not subscribe to drafts to derive labels.
- Unit conversion is shared deterministic contract logic, not a component calculation. Components choose which already-validated representation to show.
- Keep the source-card/card-order implementation bounded to current-session latest samples. Persistent saved/offline fleet rows, scrolling history, and comparison selection are not part of this spec.
- Add no third-party packages.
