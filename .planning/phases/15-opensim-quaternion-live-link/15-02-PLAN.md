<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ROS graph to bridge callbacks | Any publisher can send malformed or high-rate Imu messages on configured topics. |
| Parameters to adapter | Topic names, frame names, timeout, status topic, and model path are operator-controlled. |
| Native adapter to ROS status | Native runtime failures must become bounded serializable state rather than escaping callbacks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-04 | Denial of Service | Imu callbacks | mitigate | Bound each callback to newest-message validation plus one adapter update, catch failures, and use finite/near-zero gating. |
| T-15-05 | Tampering | Status JSON | mitigate | Build JSON from owned scalar state with a fixed schema/version and `json.dumps`; do not concatenate incoming strings. |
| T-15-06 | Repudiation | Fault transitions | mitigate | Log each state/reason transition and publish role-specific counters/errors. |
| T-15-07 | Spoofing | Master/slave identity | accept | This local prototype trusts configured ROS topic names; role is fixed by the subscription callback rather than message frame text. |
| T-15-SC | Tampering | Package supply chain | accept | This plan adds no package-manager dependency. |
</threat_model>
