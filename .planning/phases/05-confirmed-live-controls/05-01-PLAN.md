# Plan 05-01: Harden Hardware Control Contract

## Objective

Extend the bridge and ROS master node from rate-only control to a typed, acknowledged control contract for filter, IMU ranges, paired rate, and effective sensor rate.

## Tasks

1. Refactor the ROS control sender so `FREQ`, `FILTER`, and `CFG` commands share one request/result path, including separate USB control connections and structured failures.
2. Extend the USB serial bridge command relay and response handling for the full command family, preserving binary-stream resumption after each command.
3. Add ROS parameters or services that validate the user-facing values and expose confirmed hardware state for filter, accel range, gyro range, paired rate, and effective rate.
4. Add focused backend tests for command building, validation, acknowledgement mapping, and failure handling.

## Verification

- `python -m py_compile` passes for modified Python modules.
- Backend tests cover successful and failed control paths without hardware.
- USB test sends one command from every control family and verifies the master stream resumes.
