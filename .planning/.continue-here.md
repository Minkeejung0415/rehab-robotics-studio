# BLOCKING CONSTRAINTS — Read Before Anything Else

> These constraints were discovered through live failures. Acknowledge them before changing the connection design.

- [ ] Do not add `Serial.printf` or other potentially blocking USB CDC writes to the TCP command hot path. With no serial reader, those writes previously delayed TCP replies until the host timed out.
- [ ] Do not forward a second physical `IDENTITY?` from `fleet_bridge_node` through the relay. The relay must answer it from the complete inventory it already validated.
- [ ] Do not reopen a fresh ESP control socket immediately after the identity probe. That experiment intermittently lost `REDPITAYA`/`START`; retain the single validated socket.
- [ ] Do not reduce `TCP_IDLE_CLIENT_TIMEOUT_MS` below the measured full-stack startup interval. The former 5000 ms value expired during a roughly 5.5-second WSL/ROS startup.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| USB diagnostics in command path | Serial output blocked firmware command processing when COM ports were not drained. | blocking | Keep diagnostics outside `handleLine`/TCP write paths and test unattended with COM3/COM4 closed. |
| Double identity ownership | Relay and fleet independently queried the same ESP socket, interleaving inventory fragments. | blocking | Relay performs one bounded physical query and serves the cached verified inventory downstream. |
| Probe/control socket swap | Closing the verified socket and immediately opening another intermittently dropped subsequent commands. | blocking | Reuse the validated socket for REDPITAYA/START. |
| Treating harness teardown as protocol failure | The latest matrix printed `ok: true` before a serial reader raised `ClearCommError` during teardown. | advisory | Evaluate the JSON result separately, then fix serial-worker shutdown later. |
